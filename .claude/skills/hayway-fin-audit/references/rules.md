# Կանոններ և բանաձևեր

Բոլոր գումարները՝ ՀՀ դրամ, Decimal ճշգրտությամբ։ Օրը՝ Երևանի ժամով (UTC+4)։
Կոդը՝ `scripts/finaudit/checks.py`։ Շեմերը՝ `config.json → thresholds`։

## Մակարդակներ

- 🔴 **crit** — գումար է կորել կամ չի եկել (պարկի մինուս)։
- 🟠 **warn** — պետք է մարդ նայի։
- ✅ **ok** — ստուգված է և ճշգրիտ համընկնում է։
- ⛔ **skip** — չի ստուգվել (տվյալ չկա / թերի է / կարգավորումը հաստատված չէ)։ Մեկ ⛔-ն էլ բավական է, որ վերնագիրը ✅ չլինի։

## Fleet-ի կատեգորիաների տեսակները (`kind`)

| kind | Ինչ է | Ելքի վերլուծության մեջ |
|---|---|---|
| `topup` + provider | Idram / Telcell / EasyPay լիցքավորում | «լիցքավորված» գումար (P) |
| `topup_fee` + provider | լիցքավորման միջնորդավճար վարորդից | պակասեցնում է P-ն |
| `payout` | ելք վարորդի հաշվից (PrimeBridge → Idram/քարտ) | վերցվում է նախ E, հետո O, հետո P |
| `payout_fee` | ելքի միջնորդավճար վարորդից | նախ P |
| `payout_refund` | չկայացած ելքի վերադարձ | E |
| `order_income` (+ party platform) | անկանխիկ, կորպ., թեյավճար, բոնուս | վաստակած (E) |
| `order_fee` (+ party platform/park) | Yandex-ի/պարկի միջնորդավճար, ԱԱՀ | անկանխիկ պատվերինը՝ նախ E, կանխիկինը՝ նախ P |
| `manual_credit` / `manual_debit` | ձեռքով ավելացում/հանում | + → E, − → նախ P |
| `ignore` | հաշվեկշիռը չի փոխում (կանխիկի տեղեկություն) | — |
| (չկա config-ում) | `unknown` → 🟠 «չդասակարգված» | + → E, − → նախ P |

`party: "platform"` = Yandex-ի կողմի գործարք (Yandex-ը պարտք է պարկին այդ գումարը կամ հակառակը)։

## 1. Փոխանցումներ բիզնես հաշվին

**Ով ինչքան պետք է փոխանցի**
- Idram / Telcell / EasyPay՝ `Σ(topup + topup_fee)` այդ համակարգի համար, ժամանակահատվածի ընթացքում = այն, ինչ
  վարորդները **ստացել են** իրենց հաշվին։ Եթե միջնորդավճարը պահվում է վարորդից, բանկ պետք է գա **ճիշտ այդքան**։
- Yandex՝ `Σ(party = platform)` = անկանխիկ եկամուտ + բոնուսներ − Yandex-ի միջնորդավճարներ/ԱԱՀ (կանխիկ պատվերների
  միջնորդավճարն էլ Yandex-ը հանում է այստեղից)։ Մինչև `formula_verified: true` անհամապատասխանությունը 🟠 է։

**Ժամանակահատված** (`cover`)
- `since_previous_receipt`, `lag_days: 1` (լռությամբ)՝ S օրվա փոխանցումը ծածկում է [նախորդ փոխանցման օրը … S−1]։
  Աշխատում է բոլոր գրաֆիկների համար (ամեն օր, 10 օրը մեկ, երկուշաբթի), հանգստյան օրերն էլ ինքնաբերաբար։
- `previous_days` (`days: n`), `previous_week` (նախորդ երկուշաբթի–կիրակի)՝ եթե պայմանագիրը այդպես է։

**Համեմատում** (S օրվա բոլոր մուտքերը այդ աղբյուրից գումարվում են)։ Համեմատվում է **միայն** `cover`-ով որոշված
ժամանակահատվածը. ուրիշ օրերի հետ համընկնումը երբեք ✅ չի դարձնում (այլապես մասնակի փոխանցումը կթաքցներ պակասը)։
1. |ստացված − սպասվող| ≤ `settlement_tolerance_amd` (1 ֏) → ✅։
2. Համընկնում է `սպասվող − համախառն × contract_fee_pct%`-ի հետ (շեղումը՝ ≤ 0,5 ֏ ամեն լիցքավորման համար, բայց ոչ ավել
   քան ծավալի 0,05%) → 🔴 **«միջնորդավճարը պահվել է ՄԵԶԱՆԻՑ»** (եթե `fee_payer: "park"`, ✅)։
3. Այլապես՝ պակաս → 🔴 (եթե պակասը 0–5% է, նշվում է «նման է միջնորդավճարի»), ավել → 🟠 (հնարավոր է՝ վարորդի
   վճարումը չի հաշվեգրվել Fleet-ում)։ Բացատրության մեջ գրվում է, եթե եկածը համապատասխանում է ժամանակահատվածի
   միայն մի մասին («մնացած օրերի գումարը չի եկել») կամ ավելի երկար ժամանակահատվածի («ստուգել cover-ը»)։
4. Նախորդ փոխանցումը քաղվածքում չկա, կամ Fleet-ի պատմությունը կարճ է → ⛔ (չի գուշակվում)։

**Գրաֆիկ**
- Վերջին փոխանցումից անցել է `max_gap_days`-ից ավել (Yandex/Idram 3, Telcell 12, EasyPay 8) → 🔴 «ուշանում է» + չփոխանցված գումարը։
- Քաղվածքի ամբողջ ժամանակահատվածում ոչ մի փոխանցում, բայց լիցքավորումներ կան → 🔴 (եթե քաղվածքը `max_gap_days`-ից
  կարճ է՝ ⛔)։
- EasyPay՝ երկուշաբթի օրը փոխանցում չկա → 🔴, երեքշաբթի էլ չկա → 🔴 «ուշանում է» (`max_gap_days: 7`)։
  Yandex/Idram՝ աշխատանքային օրը չկա → 🟠։
- «Սպասվում է» սյունակը՝ Fleet-ում արդեն հաշվեգրված, բանկ դեռ չհասած գումարը։

## 2. Լիցքավորումներ (ստուգվող օրը)

- Մեկ լիցքավորում ≥ `large_topup_amd` (10 000 ֏, ներառյալ 10 000-ը) → 🟠, վարորդ, հեռախոս, համակարգ, ժամ։
- Մի քանի լիցքավորում, ամեն մեկը < 10 000, բայց օրվա ընդամենը ≥ 10 000 → 🟠 «մասնատված»։
- Բացասական լիցքավորում (չեղարկում) → 🟠։
- Օրվա ընդհանուրը՝ ըստ պարկի և համակարգի (Idram / Telcell / EasyPay առանձին)։

## 3. Ելք՝ վաստակա՞ծ, թե՞ լիցքավորված գումարից

Ամեն վարորդի համար 35 օրվա գործարքները ժամանակագրական կարգով, հաշիվը բաժանված է 4 «գրպանի»՝
- **E** — պատվերներից վաստակած, **P** — լիցքավորված, **O** — 35 օր առաջ եղած դրական մնացորդը (ծագումը անհայտ, համարվում է օրինական),
  **D** — պարտք։ Սկզբնական մնացորդը = այսօրվա հաշվեկշիռ − 35 օրվա գործարքները։
- Մուտքերը նախ փակում են պարտքը, հետո գնում են իրենց գրպանը։
- Միջնորդավճարներ, տուգանքներ, կանխիկ պատվերների միջնորդավճարներ → նախ P (լիցքավորումը հենց դրա համար է), հետո O, հետո E։
- Անկանխիկ պատվերի միջնորդավճար → նախ E։
- **Ելք** → նախ E, հետո O, հետո P։ Եթե P-ից վերցված մասը ≥ `withdrawal_from_topup_min_amd` (1 000 ֏) → 🟠։
  Եթե գրպանները չեն բավարարում (ելքը > հաշվեկշիռ) → 🔴 «ելք՝ հաշվեկշռից ավել»։
- Սա վարորդի օգտին մեղմ կանոն է. 🟠 գալիս է միայն այն ժամանակ, երբ ելքը **հաստատ** գերազանցում է վաստակածը։
- Եթե հաշվեկշիռը անհայտ է կամ վերցված է Fleet-ի տվյալներից հետո, տողում գրվում է «մոտավոր», իսկ «ավել» դեպքը
  առանձին 🟠 է (`payout_over_balance_approx`). ճշգրիտ դեպքերը մնում են 🔴։
- Նույն պահի գործարքներից մուտքերը մշակվում են առաջ (պատվերի եկամուտը՝ նրա միջնորդավճարից առաջ)։

## 4. PrimeBridge ↔ Fleet

Համընկնում՝ նույն վարորդը (Fleet ID կամ հեռախոսի վերջին 8 թիվը), ±48 ժամ, և `|Fleet ելք| = PB գումար` կամ `PB գումար + PB միջնորդավճար`։
Զույգերը կազմվում են **բոլոր** բեռնված տողերի վրա միասին (ոչ միայն ստուգվող օրվա). նախ հաջողվածները, հետո
ամենամոտ ժամանակով։ Այսպես հարևան օրը չի «գողանում» պահումը, և կրկնակի փոխանցումը չի թաքնվում։ Հաղորդվում է միայն ստուգվող օրը։
- PB-ն հաջողությամբ ուղարկել է, Fleet-ում պահում չկա → 🔴 կորուստ (գումար + միջնորդավճար)։ Կրկնակի փոխանցումն էլ է այստեղ։
- PB-ն հաջողությամբ ուղարկել է, բայց Fleet-ում գումարը վերադարձվել է վարորդին → 🔴 «ստացել է երկու անգամ»։
- PB միջնորդավճար > 0, բայց Fleet-ում վարորդից չի պահվել (ոչ ելքի մեջ, ոչ առանձին `payout_fee` ±48 ժամում, ամեն
  տող՝ մեկ անգամ) → 🔴 «վճարել ենք մենք»։
- Fleet-ում պահվել է, PB-ում չկա → 🟠։ Fleet-ում վերադարձ կա, բայց չկայացած PB չկա → 🟠։
- PB-ն չի կայացել, Fleet-ում պահվել է, վերադարձ չկա → 🟠 (վարորդի գումարը կախված է)։
- PB-ի կարգավիճակը՝ `files.primebridge.status_failed|status_pending|status_ok` (regex, հայերեն/ռուսերեն/անգլերեն)։
  Անծանոթ կամ դատարկ կարգավիճակը համարվում է **ուղարկված** (որ պահման բացակայությունը երևա) + 🟠 նշում։

## 5–8. Այլ

- Ձեռքով ավելացում ≥ `manual_credit_alert_amd` → 🟠 (ով է ստեղծել, նկարագրություն)։
- Պարտք ≥ `debt_alert_amd` → 🟠 ցուցակ; ընդհանուր պարտքը՝ թվերում։
- Բանկ՝ օրվա մուտք/ելք ըստ աղբյուրի; չճանաչված մուտք → 🟠; մնացորդի շղթան չի կապվում → 🟠; մնացորդը < 0 → 🔴։
- Դիրք՝ `բանկի մնացորդ + PB մնացորդ + սպասվող մուտքեր − Σ(վարորդների դրական մնացորդներ)`, ամենը՝ ստուգվող օրվա
  վերջի դրությամբ։ < 0 → 🔴 (եթե կատեգորիաներն ու Yandex-ի բանաձևը հաստատված են, այլապես 🟠)։
  Բանկի մնացորդը անհայտ է (ոչ սյունակ, ոչ `--bank-balance`) կամ գոնե մեկ վարորդի հաշվեկշիռը անհայտ է → ⛔։

## Տվյալների ամբողջականություն (⛔)

- Fleet-ի չկարդացված տող, պարկ առանց տվյալի, պարկ, որ շաբաթը աշխատել է, բայց ստուգվող օրը 0 գործարք ունի։
- Վարորդների հաշվեկշիռ չկա կամ վերցված է Fleet-ի տվյալներից հետո (API-ով հաշվեկշիռները բերվում են գործարքներից առաջ)։
- Բանկի/PB-ի ֆայլը չի հասնում ստուգվող օրվան, PB-ում միջնորդավճարի սյունակ չկա (`fee_column_required`)։
