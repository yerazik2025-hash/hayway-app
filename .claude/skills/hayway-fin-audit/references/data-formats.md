# Տվյալների աղբյուրներ և ձևաչափեր

Բոլոր ֆայլերը՝ CSV (UTF-8 կամ Windows-1251, `,` `;` կամ tab), XLSX կամ JSON։ Վերնագրի տողը սկրիպտը ինքն է գտնում
(բանկային քաղվածքներում վերևում վերնագրեր են լինում)։ Սյունակների անունները՝ `config.json → files.*.columns`
(յուրաքանչյուր դաշտի համար մի քանի հնարավոր անուն, հայերեն/ռուսերեն/անգլերեն)։ Չկարդացված տողը չի կորչում.
այն հայտնվում է հաշվետվությունում (բանկի և PB-ի դեպքում՝ 🔴)։

## 1. Yandex Fleet (երկու պարկ՝ `taxi`, `delivery`)

### Ա. API-ից (`--fleet api`)

Միջավայրի փոփոխականներ (երբեք ֆայլում)՝
```
FLEET_TAXI_PARK_ID, FLEET_TAXI_API_KEY, [FLEET_TAXI_CLIENT_ID]          # լռությամբ taxi/park/<PARK_ID>
FLEET_DELIVERY_PARK_ID, FLEET_DELIVERY_API_KEY, [FLEET_DELIVERY_CLIENT_ID]
```
Սրանք նույն բանալիներն են, որոնցով HayWay-ի `fleet-sync`-ը արդեն աշխատում է։ Կանչվում են միայն կարդալու endpoint-ներ՝
`/v2/parks/transactions/list`, `/v2/parks/transactions/categories/list`, `/v1/parks/driver-profiles/list`։
Գործարքները բերվում են ստուգվող օրից 35 օր առաջ → մինչև հիմա, հաշվեկշիռները՝ հիմա։

### Բ. Ֆայլից (`--fleet-file taxi=…csv --fleet-file delivery=…csv --fleet-period FROM:TO`)

Օրինակ՝ Supabase-ի համաժամացված աղյուսակից արտահանված։ Մեկ տող = մեկ գործարք։

| Սյունակ | Պարտադիր | Նշում |
|---|---|---|
| `event_at` | այո | ISO ժամանակ գոտիով (`2026-11-16T10:00:00+04:00`), առանց գոտու = Երևան |
| `driver_id` | այո | Fleet-ի driver_profile_id |
| `category_id` | այո | Fleet-ի կատեգորիայի ID (ոչ անունը) |
| `amount` | այո | + վարորդի հաշվին, − հաշվից |
| `id`, `category_name`, `order_id`, `created_by`, `description`, `park` | ոչ | `order_id`-ն պետք է անկանխիկ/կանխիկ պատվերները տարբերելու համար |

`--fleet-period`-ը՝ ֆայլի **լրիվ** ծածկած օրերը (ներառյալ)։ Եթե չտրվի, որոշվում է գործարքներից, և վերջին օրը կարող է թերի համարվել։

**Վարորդներ** (`--drivers-file`)՝ `park, driver_id, name (կամ first_name/last_name), phone, balance, balance_at`։
`balance_at`-ը՝ երբ է վերցված հաշվեկշիռը. գործարքների ֆայլը պետք է հասնի մինչև այդ պահը։

## 2. Բիզնես հաշվի քաղվածք (`--bank file [--bank-period FROM:TO]`)

Պետք է՝ ամսաթիվ, գումար (նշանով, կամ գումար + ուղղության սյունակ Д/К, Դեբետ/Կրեդիտ, D/C, կամ առանձին մուտք/ելք
սյունակներ), ումից/ում, նպատակ, մնացորդ։ Առանց մնացորդի սյունակի տուր `--bank-balance` (օրվա վերջի մնացորդը),
այլապես «մինուս ենք թե ոչ»-ը ⛔ է։ Անծանոթ ուղղության նշանով տողը չի կարդացվում (🔴 նշում), չի գուշակվում։
Ժամանակահատվածը՝ ստուգվող օրից առնվազն 35 օր հետ (որ գտնվի նախորդ Telcell/EasyPay փոխանցումը)։
`--bank-period`-ը տուր, եթե քաղվածքի վերջին օրը գործարք չունի (կիրակի)։

Աղբյուրը որոշվում է `bank.classify` կանոններով (regex, մեծատառ/փոքրատառ անկախ)՝ նախ «ումից» դաշտով, և միայն եթե
ոչ մի կանոն չհամընկավ՝ «ումից | նպատակ» տեքստով։ Ամեն փուլում առաջին համընկնողը հաղթում է։ Իրական քաղվածքով ստուգիր, որ բոլոր փոխանցողները ճանաչվում են։

## 3. PrimeBridge (`--pb file [--pb-period FROM:TO] [--pb-balance AMOUNT]`)

| Սյունակ | Պարտադիր | Նշում |
|---|---|---|
| ամսաթիվ/ժամ | այո | |
| գումար | այո | վարորդին ուղարկված |
| `driver_id` կամ հեռախոս | այո | Fleet ID-ն ավելի հուսալի է |
| միջնորդավճար | այո* | առանց դրա ⛔. *եթե PrimeBridge-ը իսկապես միջնորդավճար չունի՝ `primebridge.fee_column_required: false` |
| կարգավիճակ | ցանկալի | `files.primebridge.status_ok/failed/pending` (regex); անծանոթը՝ «ուղարկված» + 🟠 նշում; առանց սյունակի՝ բոլորը հաջողված |
| `park`, `id`, ուր (Idram/քարտ) | ոչ | |

Արտահանիր ստուգվող օրը ± 1 օր (կեսգիշերի ելքերի համար)։

## 2ա. IDBank-ի PDF քաղվածք (`statement@idbank.am` կամ IDBanking)

PDF-ը հին ArmSCII-8 տառատեսակով է. `scripts/finaudit/idbank.py`-ը այն կարդում է `pdftotext -layout`-ով (poppler;
Windows՝ `winget install oschwartz10612.Poppler`) և վերածում հայերենի։ Ժամանակահատվածը, հաշվի համարը, սկզբնական և
վերջնական մնացորդը վերցվում են վերնագրից։ **Ամեն քաղվածք ստուգվում է իր իսկ ամփոփման հետ**. սկզբնական + մուտքեր −
ելքեր = վերջնական, և կարդացված տողերի գումարը = տպված ընդհանուրներին։ Եթե չի համընկնում, քաղվածքը չի օգտագործվում
(սխալ), որովհետև մեկ բաց թողնված տողը կարող է թաքցնել փոխանցում։ Մնացորդը՝ ամեն օրվա վերջում («Օրվա վերջի դրությամբ»)։
Մի քանի հաշիվ՝ `--bank` կրկնելով. մնացորդը հաշվվում է ամեն հաշվի համար առանձին, իսկ ստուգվող օրը պետք է ծածկի ամեն քաղվածք։
`bank.accounts`-ում նշիր հաշիվները (`{"<համար>": {"name": "Հիմնական · տաքսի", "required": true}}`). եթե `required`
հաշվի քաղվածքը չի տրվել, ստուգումը ⛔ է, որովհետև միայն երկրորդական հաշիվներով «ամեն ինչ ճիշտ է» ասել չի կարելի։

## 3ա. Idram / Telcell / EasyPay-ի հաշվետվություն (`--provider-report idram=file [--provider-report-period idram=FROM:TO]`)

Նրանց նամակներով եկող վճարումների ցուցակը (CSV/XLSX)։ Մեկ տող = մեկ վճարում։ Սյունակների անունները՝
`files.provider_report.columns` (իրական նմուշը տեսնելուց հետո ճշտել)։

| Դաշտ | Պարտադիր | Նշում |
|---|---|---|
| ամսաթիվ/ժամ | այո | |
| գումար (վճարած) և/կամ հաշվեգրված (զուտ) | այո | եթե մեկը չկա, հաշվվում է միջնորդավճարով |
| միջնորդավճար | ցանկալի | `գումար − միջնորդավճար` պետք է = `հաշվեգրված` (≤ 1 ֏), այլապես տողը 🔴 նշումով դուրս է մնում |
| վճարման համար, հեռախոս, հաշիվ (Fleet ID) | գոնե մեկը | համարը օգնում է, եթե Fleet-ի նկարագրության մեջ էլ կա |
| կարգավիճակ | ոչ | «չի նստել / не зачислен / not credited…» (`status_not_credited`) → վճարողի պնդումը, ստուգվում է ցանկացած օրվա համար |

Մի քանի ֆայլ՝ `--provider-report` կրկնելով։ Նույն ձևով՝ `telcell=`, `easypay=`։

Իրական ձևաչափեր (2026-11).
- **Telcell** (`info@telcell.am`, ամեն օր 05:00, `Стандартный отчёт.xlsx`)՝ `ID платежа`, `Дата и время`, `Реквизиты`
  (վարորդի 6-նիշ կոդը), `Сумма` (վճարած), `№ чека`։ Միջնորդավճարի սյունակ չկա. զուտը հաշվվում է `contract_fee_pct`-ով։
- **Idram «հարցում»** (`*@edram.am`)՝ `Ամսաթիվ`, `Գործարք`, `Բաժանորդ` (6-նիշ կոդ), `Գումար` → `scripts/mail_claims.py`։

**Վարորդի կոդը** (`Բաժանորդ` / `Реквизиты`)՝ այն թիվը, որ վարորդը մուտքագրում է տերմինալում։ Ծրագիրը կոդը կապում է
վարորդի հետ նախ ինքնուրույն (երբ նույն կոդով վճարումը գտնվել է Fleet-ում իր համարով), ապա `--driver-codes codes.csv`-ից
(`code,driver_id[,park]`)։

## 3բ. Մի քանի պայմանագիր նույն համակարգով (Idram-ի տաքսի և Delivery)

Idram-ի հետ կա առանձին պայմանագիր տաքսու և Delivery-ի համար, և փոխանցումները գալիս են առանձին՝ նպատակում պայմանագրի համարով։
`config.json`-ում.
```json
"providers": {
  "idram": null,
  "idram_taxi":     {"type": "idram", "name": "Idram · տաքսի",    "parks": ["taxi"],     "contract_no": "ՎՀ-…/…",   "contract_fee_pct": 2.0},
  "idram_delivery": {"type": "idram", "name": "Idram · Delivery", "parks": ["delivery"], "contract_no": "ՎՀ-…/…-1", "contract_fee_pct": 2.0,
                     "expect_weekdays": [], "max_gap_days": 10}
},
"bank": {"classify": [
  {"source": "idram_delivery", "counterparty": "idram|իդրամ", "purpose": "Delivery|…-1"},
  {"source": "idram_taxi",     "counterparty": "idram|իդրամ", "purpose": "ՎՀ-…/…(?![-\\d])"}
]}
```
`null`-ը հանում է լռելյայն պրովայդերը։ Նոր բանալին ժառանգում է իր `type`-ի լռելյայն արժեքները։ Delivery-ին Idram-ը
փոխանցում է միայն վճարում եղած օրերին, դրա համար `expect_weekdays: []`։

## 4. Ելք (`--out DIR`)

`DIR/<YYYY-MM-DD>/report.md` (ամբողջական), `summary.txt` (Telegram/push), `report.json` (մեքենայական)։
Այս թղթապանակը git-ում չի մտնում (`.gitignore`)։
