# HayWay · ամենօրյա ֆինանսական ստուգում

Տիրոջ (Գարիկ) խնդրանքը՝ ամեն օր հատ առ հատ ստուգել, որ բոլոր փոխանցումները ճիշտ են արված,
պարկը մինուս չի գնում, միջնորդավճարները պահվում են **վարորդներից, ոչ թե մեզանից**, և զգուշացնել
մեծ լիցքավորումների ու լիցքավորված գումարից արված ելքերի մասին։ Նույնը՝ տաքսու և առաքման պարկերի համար։

## Ոսկե կանոններ (չխախտել)

1. **Միայն կարդալ։** Fleet-ում, PrimeBridge-ում, բանկում ոչինչ չփոխել, գործարք չստեղծել, գումար չուղարկել։
   Ուղղումները անում է մարդը։ **Նամակները միայն նախագիծ են**. Idram/Telcell/EasyPay/Yandex-ին ոչինչ չուղարկել
   առանց տիրոջ հստակ «այո»-ի հենց այդ նամակի համար։
2. **Հաշվարկը անում է սկրիպտը, ոչ թե դու։** Թվերը մի՛ գումարիր ձեռքով, մի՛ կլորացրու, մի՛ «գնահատիր»։
   Բոլոր թվերը՝ `scripts/audit.py`-ից (Decimal, առանց float-ի)։ Եթե թիվը չկա հաշվետվությունում, ասա «չկա»։
3. **Տվյալ չկա = ⛔, ոչ թե ✅։** Եթե աղբյուրը (Fleet, բանկ, PrimeBridge, հաշվեկշիռներ) բացակայում է
   կամ չի ծածկում օրը, հաշվետվությունը ասում է «Ստուգումը թերի է»։ Երբեք մի՛ գրիր «ամեն ինչ կարգին է»,
   եթե վերնագիրը ✅ չէ։
4. **Ամեն 🔴 ստուգիր հում տողերով** նախքան տիրոջը ուղարկելը. բաց քաղվածքի/Fleet-ի տողը և համոզվիր, որ
   սխալը իրական է (ոչ թե ֆայլի ձևաչափի)։ Եթե կասկածում ես, գրիր՝ «ստուգել», մի՛ թաքցրու։
5. **Տվյալները գաղտնի են։** config.json, քաղվածքներ, հաշվետվություններ՝ երբեք git-ում (repo-ն հրապարակային է),
   երբեք արտաքին ծառայություններում։ Բանալիները՝ միայն միջավայրի փոփոխականներում։

## Ամենօրյա քայլեր (ամեն առավոտ, նախորդ օրվա համար)

Ստուգվող օրը = **երեկ** (Երևանի ժամով), եթե տերը այլ օր չի ասել։

1. **Հավաքիր տվյալները** (ձևաչափերը՝ `references/data-formats.md`)՝
   - **Fleet**՝ երկու պարկի գործարքները վերջին 35 օրվա համար + վարորդների հաշվեկշիռները։
     Ամենահեշտը՝ `--fleet api` (բանալիները `FLEET_TAXI_*`, `FLEET_DELIVERY_*`)։
     Եթե բանալիներ չկան, բայց կա Supabase-ի համաժամացված պատճենը, արտահանիր CSV՝ նույն սյունակներով։
   - **Բիզնես հաշվի քաղվածք**՝ առնվազն 35 օր հետ մինչև ստուգվող օրը ներառյալ (CSV/XLSX, մնացորդի սյունակով;
     եթե չկա՝ `--bank-balance <օրվա վերջի մնացորդը>`)։
   - **PrimeBridge**՝ ելքերի ցուցակը ստուգվող օրվա և հարևան օրերի համար (ամսաթիվ, վարորդ, գումար, միջնորդավճար, կարգավիճակ)։
   - **Տիրոջ փոստից (Gmail-ը միայն կարդալու համար. ոչինչ չուղարկել, չջնջել, չնշել)**՝ կցված ֆայլերը պահիր `data/`-ում.
     | Ինչ | Ումից / թեմա | Ինչպես տալ |
     |---|---|---|
     | Telcell-ի ամենօրյա վճարումներ | `info@telcell.am`, «HayWey DD.MM.YYYY 05:00», `Стандартный отчёт.xlsx` | `--provider-report telcell=file.xlsx` |
     | Idram «վճարել է, բայց չի նստել» | `*@edram.am`, «Իդրամ հարցում» (Ամսաթիվ, Գործարք, Բաժանորդ, Գումար) | պահիր նամակի տեքստը `.txt`, հետո `python scripts/mail_claims.py *.txt --out data/idram_claims.csv` → `--provider-report idram_taxi=data/idram_claims.csv` (Delivery-ի դեպքում՝ `idram_delivery=`) |
     | Idram-ի ամսական ակտ | `accounting@email.idram.am`, «Փոխադարձ Հաշվարկների Ստուգման ԱԿՏ» (PDF, ամեն պայմանագրին՝ մեկը) | `python scripts/monthly_act.py --act ... --bank ...` (ստորև) |
     | IDBank-ի քաղվածք | `statement@idbank.am`, «ACCOUNT STATEMENT ...» (PDF, ամեն հաշվին՝ մեկը) | `--bank file.pdf` (մի քանի հաշիվ՝ կրկնելով) |
     Ամենօրյա ստուգման համար բանկի քաղվածքը պետք է հասնի ստուգվող օրվան. ամսականը բավական չէ (⛔)։
     Ոչինչ մի՛ գուշակիր. եթե նամակում տվյալ չկա, գրիր հաշվետվությունում, որ չկա։
2. **Գործարկիր**՝
   ```bash
   cd scripts
   python audit.py --config ../config.json --fleet api \
       --bank /path/bank.xlsx --bank-period 2026-10-13:2026-11-17 \
       --pb /path/pb.csv --pb-period 2026-11-16:2026-11-18 \
       --provider-report idram=/path/idram_16.11.xlsx \
       --out ../reports            # reports/ git-ում չի մտնում
   ```
   `--date`-ը չտալու դեպքում ստուգվում է երեկը։ Ելքի կոդ՝ 0 = ստուգված, 2 = կան 🔴, 3 = թերի (⛔), 1 = գործարկումը ձախողվեց։
3. **Կարդա** `reports/<օր>/report.md`-ը։ Ամեն 🔴-ի համար բաց համապատասխան հում տողը (կանոն 4)։
4. **Ուղարկիր տիրոջը**՝ `summary.txt`-ի տեքստը (կարճ, Telegram-ի համար) + ամբողջ `report.md`-ը։
   Ավելացրու միայն այն, ինչ ինքդ ստուգեցիր հում տողերում։ `report.json`-ը մեքենայական է (հավելվածի համար)։
5. **Նամակներ վճարողներին** (`reports/<օր>/letters/<idram|telcell|easypay|yandex>.md` + `.csv` կից ցուցակ)։
   Սկրիպտը նախագիծ է պատրաստում ամեն 🔴-ի համար, որտեղ գումար է պակասել կամ չի եկել՝ պակաս փոխանցում,
   միջնորդավճար մեզանից, բաց թողնված/ուշացած փոխանցում (Yandex-ի համար՝ միայն `formula_verified`-ից հետո)։
   Ցույց տուր նամակը տիրոջը, նշիր `[լրացնել]` բացերը (`config.json → company`, `providers.*.email/contract_no`)։
   Ուղարկիր միայն տիրոջ «այո»-ից հետո և միայն եթե ունես էլ. փոստի գործիք. այլապես տերն է ուղարկում։
   Եթե նույն նամակը երեկ արդեն ուղարկվել է, մի՛ կրկնիր, նշիր հաշվետվությունում, որ պատասխան չկա։
6. Եթե ելքի կոդը 1 է կամ ⛔ կա, ասա՝ **որ աղբյուրը** չկա և **ինչ է պետք** այն ստանալու համար։

## Ամսական (Idram-ի ակտը ստանալուն պես)

Idram-ը ամսվա սկզբին ուղարկում է ակտ ամեն պայմանագրի համար և գրում է. **5 աշխատանքային օրում չպատասխանելու դեպքում
ակտը համարվում է համաձայնեցված**։ Այդ պատճառով ակտը ստուգիր նույն օրը.
```bash
python scripts/monthly_act.py --config config.json --act act_taxi.pdf --act act_delivery.pdf \
    --bank statement_1.pdf --bank statement_2.pdf [--fleet-file taxi=... --fleet-file delivery=...]
```
Ստուգվում է՝ ակտը կապվում է (մնացորդ + հավաքագրված − փոխանցված − միջնորդավճար = վերջնական մնացորդ), միջնորդավճարը
= պայմանագրի % (Idram՝ 2%), «փոխանցվել է» = բանկ եկածը այդ պայմանագրից, (Fleet-ով) վարորդներին նստածը = հավաքագրված −
միջնորդավճար։ 🔴-ի դեպքում տիրոջը անմիջապես ասա և պատրաստիր պատասխանի նախագիծ Idram-ին (ուղարկում է տերը)։

Ամեն 🔴, որ նշանակում է վճարողից պակաս/չեկած գումար → ✉️ նամակի նախագիծ այդ վճարողին։

Գրաֆիկը (ինչպես ասել է տերը)՝ Yandex՝ ամեն օր, Idram՝ ամեն օր, Telcell՝ 10 օրը մեկ, EasyPay՝ ամեն երկուշաբթի։

## Առաջին կարգավորում (մեկ անգամ, տիրոջ հետ)

Մինչև այս քայլերը արված չեն, հաշվետվությունը ⛔ «նախնական» է, և դա ճիշտ է։

1. `cp config.example.json config.json`
2. **Fleet-ի կատեգորիաներ**՝ `python scripts/fleet_setup.py --config config.json --write`։
   Սկրիպտը ցույց է տալիս պարկի իրական կատեգորիաները և առաջարկում՝ որն է Idram/Telcell/EasyPay լիցքավորում,
   որն է ելք (PrimeBridge), որը միջնորդավճար։ **Աղյուսակը ցույց տուր տիրոջը**, ուղղիր սխալները config.json-ում,
   և միայն նրա «այո»-ից հետո դիր `"categories_verified": true`։
3. **Պայմանագրային տոկոսներ**՝ `providers.<idram|telcell|easypay>.contract_fee_pct` և ով է վճարում
   (`fee_payer: "driver"`՝ տիրոջ ասածով)։ Եթե տոկոսը անհայտ է, թող `null` (պակասը միևնույնն է 🔴 կլինի)։
4. **Yandex-ի բանաձևը**՝ սպասվող = Fleet-ում `party: "platform"` գործարքների գումարը (անկանխիկ եկամուտ − Yandex-ի
   միջնորդավճար/ԱԱՀ ...)։ Մեկ իրական շաբաթով համեմատիր բանկի հետ. եթե համընկնում է, `yandex.formula_verified: true`։
   Մինչ այդ Yandex-ի անհամապատասխանությունը 🟠 է, ոչ 🔴։
5. **Բանկ**՝ իրական քաղվածքով ստուգիր, որ `bank.classify` կանոնները ճանաչում են Yandex/Idram/Telcell/EasyPay/PrimeBridge-ը,
   և սյունակները կարդացվում են (`files.bank.columns`)։
6. **Ժամանակահատվածներ**՝ լռությամբ փոխանցումը ծածկում է նախորդ փոխանցումից մինչև երեկ (`since_previous_receipt`, `lag_days: 1`)։
   Եթե հաշվետվությունը գրում է «գումարը ճշգրիտ համընկնում է այլ օրերի հետ», ուղղիր `cover`-ը։

## Եթե ինչ-որ բան չի համընկնում

- «Չդասակարգված կատեգորիա» → ավելացրու config-ում (տիրոջ հաստատմամբ), հետո վերագործարկիր։
- «Չճանաչված մուտք» → հարցրու տիրոջը՝ ինչ է, ավելացրու `bank.classify` կանոն։
- «Ելք լիցքավորումից» → սա զգուշացում է, ոչ մեղադրանք. տերը որոշում է։ Աղյուսակում կա՝ որքանն է պատվերներից, որքանը լիցքավորումից։
- Նոր կանոն/շեմ տերը ուզում է → փոխիր `config.json`-ի `thresholds`-ը, ոչ թե կոդը։ Կոդը փոխելուց հետո՝
  `cd scripts && python -m unittest discover -s tests` (բոլոր թեստերը պետք է անցնեն)։
